## Écarts constatés

- **E2, cas 1 : une date de retour passée n'est pas saisissable.** `DateField.tsx:31` (Android) et `:62` (iOS) fixent `minimumDate` à la date de début (`LoanForm.tsx:88`), et la valeur par défaut est cette date (`LoanForm.tsx:21-26`). Le refus existe et est prouvé par script (`validateLoanForm` appelle toujours `canLend`, `loanForm.ts:37-38`), mais à l'écran il n'est atteignable que si l'horloge change entre l'ouverture du formulaire (date de début figée au montage) et l'envoi. Statut : ✅ script ; écran = constat « non atteignable », étape d'horloge facultative. Ce n'est pas un défaut : c'est une protection amont plus stricte que la règle.
- **E3, cas 3 : les contextes ne revalident pas les champs.** `addEquipment` (`DataContext.tsx:99-111`) et `planAddLoan` (`loanWrites.ts:20-44`) n'appellent ni `validateEquipmentName` ni `validateFirstName` : un appel direct avec un nom vide serait enregistré. Seuls les formulaires (`EquipmentForm.tsx:40-45`, `LoanForm.tsx:44-49`) bloquent ; l'inscription, elle, revalide dans le contexte (`AuthContext.tsx:68-79`). Aucun chemin d'interface n'y mène : le critère (« enregistrement bloqué, erreur sous le champ ») est satisfait. Simple observation, sans statut ❌.

## Étapes pour Expo Go

État de départ : lancer `npx expo start`, ouvrir dans Expo Go. Si le catalogue n'affiche pas les **7 équipements de démonstration** (données déjà modifiées), noter l'état réel avant de commencer : les comptes ci-dessous s'entendent « nombre au départ + changements ». Cette série est indépendante de celle de PC-42 : elle peut se jouer sur des données neuves ou sur l'état laissé par PC-42 ; elle utilise `Tablette graphique`, disponible dans les deux cas.

1. Cas 3 (champs vides), formulaire d'équipement : « + Ajouter », ne rien saisir, « Enregistrer ». Attendu : `Le nom est obligatoire.` sous Nom et `La catégorie est obligatoire.` sous Catégorie ; l'écran reste ouvert ; aucune carte ajoutée. Saisir uniquement des espaces dans Nom : même erreur. Taper un caractère : l'erreur du champ disparaît.
2. Cas 3, formulaire de prêt : fiche `Tablette graphique` → « Prêter », laisser prénom et nom vides, « Enregistrer le prêt ». Attendu : `Le prénom est obligatoire.` et `Le nom est obligatoire.` sous leurs champs ; aucun prêt créé (la fiche reste « Disponible »).
3. Cas 1 (date passée) : sur ce même formulaire, ouvrir le sélecteur de la date de retour prévue. Noter ce que le sélecteur permet : attendu par le code, aucune date antérieure à aujourd'hui sélectionnable (écart E2). Étape facultative, à la seule discrétion de l'auteur : ouvrir le formulaire, avancer l'horloge de l'appareil d'un jour, revenir dans l'application, saisir prénom `Test` et nom `Emprunteur`, « Enregistrer le prêt » : attendu `La date de retour prévue ne peut pas être antérieure à aujourd'hui.` sous le champ date ; remettre l'horloge ensuite.
4. Cas 2 : créer un vrai prêt sur `Tablette graphique` (`Test` `Emprunteur`, retour + 3 jours) ; « Modifier », état `Hors service`, « Enregistrer ». Attendu : le formulaire reste ouvert, message rouge `Enregistrez le retour avant de passer l'équipement hors service.` au-dessus du bouton ; revenir à la fiche : état toujours « Bon état ». Changer seulement la description : enregistrement accepté.
5. Cas 2, suite : « Enregistrer le retour », puis « Modifier » → `Hors service` → « Enregistrer » : accepté, badge « Indisponible ». Remettre `Bon état` (nettoyage).
